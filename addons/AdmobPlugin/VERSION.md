## What the patches change

### 0001 — UMP privacy options + debug geography (M9-01; 3 files, +73 / −2)

1. `ConsentConfiguration.java` — `debug_geography` accepts any `java.lang.Number`
   (Godot passes GDScript ints as `Long`; v6.0 only accepted `Integer` and
   silently ignored the value — upstream issue #120, still open; fixed in
   upstream v7.0, which targets Godot 4.7).
2. `AdmobPlugin.java` — three UMP calls exposed to Godot:
   `can_request_ads()` → `ConsentInformation.canRequestAds()`,
   `get_privacy_options_requirement_status()` →
   `ConsentInformation.getPrivacyOptionsRequirementStatus()` (`"REQUIRED"` /
   `"NOT_REQUIRED"` / `"UNKNOWN"`), `show_privacy_options_form()` →
   `UserMessagingPlatform.showPrivacyOptionsForm()` + new signal
   `privacy_options_form_dismissed(Dictionary)`. Not present upstream in v6.0,
   v7.0 or `main` (checked 2026-09-22).
3. `Admob.gd` (GDScript facade template) — the same three methods plus
   `has_privacy_options_api()` (true only when the native plugin registered the
   new signal, i.e. the patched AAR is installed) and the forwarded signal.

### 0002 — RequestConfiguration value conversion (TASK/041; 2 Java files, +93 / −21)

4. `AdmobConfiguration.java` — reads what Godot 4.6 actually sends instead of the
   v6.0 casts: ints (`tag_for_child_directed_treatment`, `tag_for_under_age_of_consent`,
   `personalization_state`) as any `java.lang.Number` → `intValue()` (was `(int)` =
   `checkcast Integer`, fails on `Long`); `test_device_ids` as `Object[]`, keeping only
   non-empty `String` entries (was `(String[])`, fails on `Object[]`); `is_real`,
   `first_party_id_enabled`, `max_ad_content_rating` type-checked. An unreadable value
   is logged (`Invalid request configuration value '<key>' …`, type only, never the
   value) and its builder setter is skipped — the SDK keeps its current value; a
   missing / non-bool `is_real` is treated as real (no test devices).
5. `AdmobPlugin.java` `set_request_configuration()` — a `RuntimeException` is caught
   and logged (`request configuration NOT applied`) instead of vanishing in Godot's JNI
   bridge, and after `MobileAds.setRequestConfiguration()` the SDK's current
   configuration is read back and logged once (`set_request_configuration(): applied …`).

### 0003 — Google Mobile Ads SDK 25.3.0 + age-restricted treatment (TASK/042; 5 files)

Promoted from the TASK/040 feasibility spike (retired in TASK/042); the spike's
diagnostic logging (`TFAT_DIAG`, per-load logs, `configure_before_initialize`) is NOT
in production.

6. `common/gradle/libs.versions.toml` — `playads` 24.9.0 → **25.3.0** (the first
   release with `RequestConfiguration.Builder.setAgeRestrictedTreatment()`; UMP 4.0.0
   comes transitively from `play-services-ads-api:25.3.0`).
7. `AdmobConfiguration.java` — new key `age_restricted_treatment` (GDScript enum sent as
   `Long`: 0 UNSPECIFIED, 1 CHILD, 2 TEEN; read through 0002's `getInt`, an unknown value
   is logged and not applied). CHILD / TEEN call `builder.setAgeRestrictedTreatment(...)`;
   UNSPECIFIED calls it with `null` — the builder's unset default (the parameter is
   `@Nullable`; GMA 25.3.0 sends -1 for null but 0 for an explicit `UNSPECIFIED`, and
   `getAgeRestrictedTreatment()` reads both back as UNSPECIFIED), so a request without an
   age treatment is exactly the SDK default, also after a reset (checked with javap).
   TFCD / TFUA are still applied unchanged (Google: "If you set age treatment setting
   and TFCD or TFUA settings, Google applies the most conservative treatment.").
   The debug-only test-device path no longer logs the advertising id or the id list
   (`Added Advertising ID as test device (value not logged)`, `Set test device IDs: <n>
   (values not logged)`).
8. `AdmobPlugin.java` — `get_applied_request_configuration()` (new, `@UsedByGodot`):
   the SDK's current configuration read back from `MobileAds.getRequestConfiguration()`
   (`age_restricted_treatment`, `max_ad_content_rating`, TFCD, TFUA,
   `personalization_state`, `test_device_ids` as a COUNT, `sdk_version`, `initialized`);
   the TASK/041 `applied …` line now also carries `age_restricted_treatment=`, and
   `initialize()` logs the configuration the SDK starts with
   (`initialize(): request configuration before MobileAds.initialize …`).
9. `Admob.gd` facade template — `age_restricted_treatment` export (default
   `UNSPECIFIED`), sent by `create_request_configuration()`; `set_request_configuration()`
   now uses that same builder; `get_applied_request_configuration()` (checks the native
   method with `has_java_method()`, because Godot 4.6's Android `JNISingleton` does not
   report plugin methods through `has_method()`).
10. `model/AdmobConfig.gd` — `enum AgeRestrictedTreatment { UNSPECIFIED = 0, CHILD = 1,
    TEEN = 2 }` + `set_age_restricted_treatment()`.

The project (not the plugin) decides the value: `MonetizationManager.
DEFAULT_AGE_RESTRICTED_TREATMENT` = **UNSPECIFIED** for every user; `AdmobBackend`
applies the request configuration ONCE before `MobileAds.initialize()`, reads it back
and does not start the SDK when the read-back differs (see
`docs/monetization/ADS_SYSTEM.md`). No age information and no Play Age Signals are used.

Rebuild vs TASK/041 AARs: only `AdmobConfiguration.class`, `AdmobPlugin.class` and
`AdmobPlugin$*.class` differ. `javac` reports 11 deprecation warnings against GMA 25.3.0
(TFCD / TFUA getters+setters — Google: replaced by the age treatment; anchored adaptive
banner size helpers) — deprecated, not removed; no error.

## Rebuild / verify

`tools/admob_plugin/README.md`. In short, from the repo root:

```
tools/admob_plugin/build_patched_plugin.sh baseline   # unpatched v6.0 == upstream release AARs
tools/admob_plugin/build_patched_plugin.sh build      # v6.0 + 0001 + 0002 + 0003 into build/, installs nothing
tools/admob_plugin/build_patched_plugin.sh verify     # committed files == v6.0 + 0001 + 0002 + 0003
```

Every patched mode also resolves the plugin's release runtime classpath and fails
unless it is `play-services-ads:25.3.0` / `play-services-ads-api:25.3.0` /
`user-messaging-platform:4.0.0`.

TASK/042 determinism (work machine, 2026-09-27): `build` in the existing clone and
`build` in a fresh upstream clone produced byte-identical AARs and generated files
(debug `a78acb22…15b6`, release `f5a563a7…20f8`); `install` (3rd build) and `verify`
(4th build) reproduced the same bytes (`BYTE-IDENTICAL`); `baseline` still reproduces
the upstream v6.0 AARs.

Why v6.0 and not v7.0 (2026-05-27): v7.0 is built against **Godot 4.7 beta1**
(`godot.properties`: `godotVersion=4.7`, `godotReleaseType=beta1`) and the
maintainer states in issue #122 that "v7.0 requires Godot 4.7+ … for Godot 4.6.x
use v6.0". This project is pinned to Godot **4.6.3** (CLAUDE.md). v7.0 also does
NOT expose the three privacy-options calls — only the #120 fix — and has no TFAT.

Google SDK support window: 24.x was *Supported* with deprecation 2027-06-30
(developers.google.com/admob/android/deprecation, read 2026-09-21); 25.3.0 is the
TFAT version selected in TASK/040 (25.4 adds `hsdp`, 25.5 raises minSdk to 24 — not
taken without a concrete blocker).

Upgrading: do NOT copy a newer release zip over this folder — that silently
drops the patches (and brings the RequestConfiguration defect back, and GMA 24.9.0
without TFAT). Re-base 0001 + 0002 + 0003 on the new upstream tag, rebuild with the
script, update this file and the release gate pin, keep `android_export.cfg` (project
configuration, not part of the release). Full notes: `docs/monetization/ADS_SYSTEM.md`,
`docs/monetization/PRIVACY_CONSENT.md`.
